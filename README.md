# Quantum Error Correction: CSS Codes and QSCD in Qiskit

EECS 298 (Quantum Information & Architecture) course project by **Rohit De, Derek Lam, and Eshwari Khurd**.

This project implements and evaluates a 3-qubit CSS (Calderbank–Shor–Steane) code combined with **Quantum Successive Cancellation Decoding (QSCD)** in Qiskit, and measures how well it protects a logical qubit against depolarizing noise.

## Background

- Entanglement is the resource that gives quantum computing its advantage, but it also makes noise catastrophic: entangling a qubit with `m` environment qubits causes a `2^m`-fold reduction in usable capacity.
- **CSS codes** protect quantum information by spreading one logical qubit across multiple physical qubits and handle bit-flip (X) and phase-flip (Z) errors independently.
- **QSCD** identifies and fixes errors one at a time using classical feedforward correction, without ever directly reading (measuring) the encoded data — proven optimal by [Renes & Wilde, 2012](https://arxiv.org/abs/1109.6519) ("Polar codes for private and quantum communication over arbitrary channels").
- Motivation: this style of syndrome-based encoder/decoder is relevant to quantum autoencoder (quantum VAE) architectures, where a small, noise-robust latent space is used for compression before quantum processing.

## Implementation

The 3-qubit repetition/CSS code has stabilizer group generated by `{Z₀Z₁, Z₁Z₂, X₀X₁X₂}`:

- **Encoder**: `H` on the data qubit to prepare `|+⟩`, then 2 CNOTs to fan it out into a 3-qubit GHZ state.
- **Syndrome extraction**: Z-type stabilizers (`Z₀Z₁`, `Z₁Z₂`) detect and locate X errors; the `X₀X₁X₂` stabilizer detects (but cannot locate) Z errors.
- **Correction**: classical feedforward — the 3-bit syndrome is decoded into an `(X correction, Z correction)` pair and applied before decoding.
- **Decoder**: inverse of the encoder (CNOTs are self-inverse, applied in reverse order) to recover the logical qubit.

### Two-pass density matrix simulation

Qiskit Aer doesn't need dynamic circuits here — instead, the correction is simulated in two passes:

1. **Pass 1**: encode → apply noise → measure the syndrome → save the full post-measurement density matrix.
2. **Pass 2**: load that density matrix, trace out the ancilla qubits, apply the classically-decoded correction, run the inverse encoder, and measure in the X basis to estimate fidelity against the original `|+⟩` state.

A density-matrix simulator (not a statevector simulator) is required because depolarizing noise produces mixed states — a statevector simulation would give incorrect fidelities.

**Key design decision:** noise is injected only on the data qubits, not the ancillas. Noise on the ancilla qubits corrupts the syndrome readout itself and breaks the correction — this was confirmed empirically during development.

## Results

- All 9 single-qubit Pauli errors (X/Y/Z on each of the 3 data qubits) are corrected with fidelity = 1.000.
- The `p = 0` (noiseless) baseline also gives fidelity = 1.0, confirming there are no pipeline bugs.
- A noise sweep (`p` from 0 to 1) compares three configurations:
  - CSS encode + QSCD correction
  - CSS encode/decode with no syndrome correction (shows the overhead cost of encoding alone)
  - A single unencoded qubit (reference floor)

  QSCD gives a clear fidelity advantage over both baselines as long as the per-gate depolarizing noise stays below a threshold.

## Running it

```bash
pip install qiskit qiskit-aer matplotlib numpy
jupyter notebook qscd_direct_noise_inject.ipynb
```

Run all cells top to bottom. The notebook will:
1. Verify the CSS encoder/decoder and syndrome decoding table.
2. Verify all 9 single-qubit Pauli errors are corrected.
3. Run a noise sweep and plot fidelity vs. noise for QSCD, no-correction, and unencoded baselines.
